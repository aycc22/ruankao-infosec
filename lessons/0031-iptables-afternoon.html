下午卷 iptables 专练：读规则、选链、写一条

本课目标：读一条规则说出效果；按场景选 INPUT 或 FORWARD 并写出一条；分清默认策略 -P 与追加 -A；会用 -s/-d/-p/--dport/-i/-o/-j 和 NEW/ESTABLISHED；NAT 只做到填空辨认。设备名与 22/80/443 入门模板回看第 28 课，这里不重讲。

开场：第 28 课会抄，本课要会改

第 28 课已经能默写 iptables -P INPUT DROP，再追加放行 22、80、443。 下午卷下一步经常是：给一段已有规则让你判效果，或给一句场景让你只写一条，或在空里填链名、接口、状态、NAT 目标。 拓扑上「网站进 DMZ、库进内网」仍用第 28 课那句，本课把命令写到网卡和地址上。

只练防御向填空：默认拒绝、按地址和端口放行、回程放行、NAT 名词对链。 不讲绕过防火墙。题目都是自编场景，不是官方原题。

零、先钉一处旧错

冲刺抽检里出现过：默认拒绝误写成追加一条 DROP。先做这一题，再进入新写法。

R1 · 要把 INPUT 的兜底改成拒绝，下午卷应填哪一条？
答案 B。-P 改的是整条内建链的兜底，目标只能是 ACCEPT 或 DROP。-A … -j DROP 只是链上一条规则；-F 是清空规则；策略不能写成 REJECT。见 iptables(8) 的 -P。
口诀（默认策略和追加规则）：要改整条链的兜底，用 -P 写成 DROP 或 ACCEPT；要在链尾加一条具体规则，用 -A。

一、先选链，再看第一条命中

题干在说什么写这条链依据（iptables(8) filter）
别人访问这台机器上的 SSH / 网站 INPUT 目的是本机套接字
这台 Linux 当网关，包转到 DMZ 或内网 FORWARD 包被路由穿过本机
限制本机进程自己发出的包 OUTPUT 本机产生的包
口诀（下午卷先选链）：包要进这台机器自己的服务，就写 INPUT；包只是从这台网关转发到别的网段，就写 FORWARD；本机进程自己发出的包，才写 OUTPUT。

链上从上往下匹配。带 -j ACCEPT、-j DROP 或 -j REJECT 的规则一旦命中，这个包的去留就定了，写在后面的相反动作不会再生效。 链上的规则都没命中，才落到 -P 的兜底。 

iptables -P INPUT ACCEPT
iptables -A INPUT -p tcp --dport 22 -j DROP
iptables -A INPUT -p tcp --dport 22 -j ACCEPT

上面三条里，SSH 会被丢掉：第一条 DROP 先命中，第二条 ACCEPT 轮不到。默认策略虽是 ACCEPT，也救不了已经被 DROP 的包。

口诀（读规则看第一条命中）：链上从上往下，第一条命中并决定去留的规则生效，写在它后面的相反动作不会再生效。

依据： iptables(8) filter 三链；-j 的内建目标会立刻决定包的命运；内建链走到末尾才由策略接手。 增删改查的 A/I/D/L/F 仍用第 28 课，本课不重列。

二、一条规则里的匹配项

参数下午卷读法书写提醒
-s来源地址只允许某台管理机时才写
-d目的地址对准 DMZ 里那台网站
-p协议，常见 tcp写 --dport 前先写协议
--dport目的端口入站服务看目的端口
-i包进来的网卡INPUT、FORWARD、PREROUTING
-o包出去的网卡FORWARD、OUTPUT、POSTROUTING
-j动作ACCEPT / DROP / REJECT，或 NAT 目标
口诀（匹配参数怎么读）：-s 看来源地址，-d 看目的地址，-p 看协议，--dport 看目的端口，-i 看进来的网卡，-o 看出去的网卡，-j 写动作。
口诀（接口能写在哪条链）：进来的网卡 -i 用在 INPUT、FORWARD 和 PREROUTING；出去的网卡 -o 用在 FORWARD、OUTPUT 和 POSTROUTING。
易错：在 INPUT 上写 -o，或在 OUTPUT 上写 -i。FORWARD 上两个都能写：-i 是从哪块网卡进来，-o 是转到哪块网卡出去。题干给的网卡名照抄，不要改成自己机器上的 ens 名称。

依据：iptables(8) 的 -s、-d、-i、-o。 --dport 见 iptables-extensions(8)。

三、NEW 与 ESTABLISHED：回程要单独放行

只写「目的端口 80 放行」时，网站的请求能过去，回包的目的端口往往不是 80（回包看的是客户端那个临时端口）。 白名单若默认 DROP，回程对不上 --dport 80，连接就建不起来。状态匹配用来放行回程。

状态手册含义（conntrack / state）下午卷怎么用
ESTABLISHED 这条连接已经双向看到过包 回程放行写它
RELATED 新连接，但挂在已有连接上（如 ICMP 差错） 和 ESTABLISHED 写在同一条
NEW 刚开始，还没双向看到包 只对题干允许的端口写 NEW
INVALID 对不上任何已知连接 本课不要求单独写
口诀（连接状态怎么放行）：先放行已经建立和相关的回程，再按端口放行新连接；其余交给默认 DROP（字头：先回程再新建）。

写法：-m state --state ESTABLISHED,RELATED。 state 模块认 INVALID、ESTABLISHED、NEW、RELATED、UNTRACKED，含义见 iptables-extensions(8) 的 conntrack 一节。 考试写 -m conntrack --ctstate 也是同一类状态，题干用哪个模块就抄哪个。

四、迷你案例：边界墙放行 DMZ 网站

自编场景。某社区卫生服务中心用一台 Linux 当边界防火墙：eth0 接外网，eth1 接 DMZ，网站是 192.168.10.8，只开放 TCP 80；eth2 接内网 192.168.20.0/24，就诊库不对外。 包是穿过防火墙转到网站，链用 FORWARD。 

iptables -P FORWARD DROP
iptables -A FORWARD -m state --state ESTABLISHED,RELATED -j ACCEPT
iptables -A FORWARD -i eth0 -o eth1 -p tcp -d 192.168.10.8 --dport 80 -m state --state NEW -j ACCEPT

外网到内网没有对应的 ACCEPT，走到链尾由 -P FORWARD DROP 兜住。 题干若要求「写明禁止直连」，把下面这条追加在放行之后： 

iptables -A FORWARD -i eth0 -o eth2 -j DROP
这条明示 DROP 不要用 -I 插到链头。插到最前会先命中，后面放行 80 的规则轮不到。
口诀（边界墙放行网站）：转发默认先拒绝；外网进来、隔离区出去、对准网站地址和端口的新连接才放行；外网直连内网没有放行规则，就由默认拒绝兜住。

五、迷你案例：本机只开 SSH 和 HTTPS

另一台机器是门户自己，题干说「只允许远程管理和 HTTPS」。包的目的是这台机器上的服务，链用 INPUT。 第 28 课题干若给了 80 就写 80；本题干没有 80，放行名单里就不出现 80。 

iptables -P INPUT DROP
iptables -A INPUT -i lo -j ACCEPT
iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT
iptables -A INPUT -p tcp -m multiport --dports 22,443 -m state --state NEW -j ACCEPT

-i lo 放行环回接口进来的包，本机进程互访才不会被默认 DROP 挡住。 22 与 443 也可以拆成两条 --dport，和 multiport 二选一，按题干空格抄。

口诀（本机只开 SSH 和 HTTPS）：入站默认先拒绝；回环和已建立的回程先放行；新连接只放 TCP 的二十二和四百四十三。

六、NAT 只做到填空辨认

下午卷若只留一个空，先认「改的是源还是目的」，再填表和链。本课不要求默写整套地址转换。

看到的要求填空手册位置
进来的包，目的地址要改到内网或 DMZ 某台机 nat 表 PREROUTING，-j DNAT DNAT 用于 PREROUTING、OUTPUT
离开的包，源地址改成固定公网地址 nat 表 POSTROUTING，-j SNAT 固定地址用 SNAT，不用 MASQUERADE
出口地址会变（拨号、DHCP） nat 表 POSTROUTING，-j MASQUERADE MASQUERADE 只在 POSTROUTING 
# 认得出即可：改目的
iptables -t nat -A PREROUTING -i eth0 -p tcp --dport 80 -j DNAT --to-destination 192.168.10.8:80
# 认得出即可：出口地址会变，改源
iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE
口诀（NAT 填空只辨认）：改目的地址用 DNAT，写在 nat 表的 PREROUTING；改源地址用 SNAT 或 MASQUERADE，写在 nat 表的 POSTROUTING；出口地址会变时用 MASQUERADE。
DNAT 只改地址。改完之后包若要转到 DMZ，filter 的 FORWARD 仍要有放行，两处空都要填。 现行手册里 SNAT 也能出现在 nat 的 INPUT（内核 2.6.36 起）；下午卷看到「包要离开本机、改源地址」，优先填 POSTROUTING。
口诀（第 31 课易错）：本机服务写成 FORWARD；网关转发写成 INPUT；默认拒绝写成 -A 追加 DROP；在 INPUT 上写 -o；先写一条匹配全部的 DROP 再追加放行；MASQUERADE 填进 PREROUTING；DNAT 填进 filter 表。

依据：iptables-extensions(8) 的 DNAT、SNAT、MASQUERADE 三节；iptables(8) 的 nat 表四条内建链。

七、动手练一练

Q1 · 外网访问 DMZ 网站，包只路过这台 Linux 网关。规则应写在？
答案 B。目的不是防火墙自己的套接字，是转发到 DMZ，所以写 filter 的 FORWARD。改目的地址才用 nat，而且那是 PREROUTING 上的 DNAT，不是这条过滤规则。
Q2 · 策略为 -P INPUT DROP。规则是 -A INPUT -p tcp -s 10.8.0.5 --dport 22 -j ACCEPT。效果是？
答案 B。链是 INPUT，管的是进本机的包；-s 限制来源；--dport 22 只放行 SSH。其余入站没命中，由默认 DROP 兜住。转发看 FORWARD，改源地址看 nat。
Q3 · 外网网卡 eth0 进来、转到内网网卡 eth2 的包要明确丢掉。哪条对？
答案 B。路过转发用 FORWARD；-i eth0 是从外网进来，-o eth2 是转到内网出去。INPUT 不能写 -o，OUTPUT 不能写 -i。D 把进出网卡写反了。
Q4 · 本机白名单里，已建立连接的回包应先写哪一条？
答案 B。ESTABLISHED 表示连接已经双向看到包，用来放行回程；RELATED 一并写上。NEW 是新连接，要配具体端口。DNAT、MASQUERADE 是 nat 目标，不是这条回程放行。
Q5 · 策略仍是 ACCEPT。先追加 -A INPUT -p tcp --dport 22 -j DROP，再追加同端口的 -j ACCEPT。SSH 会怎样？
答案 B。规则是 -A INPUT -p tcp --dport 22 -j DROP 在前，同端口 ACCEPT 在后。第一条命中后包已经丢掉，后面的 ACCEPT 不会再生效。策略只处理整条链都没命中的包。
Q6 · 出口公网地址由 DHCP 分配、会变化。内网上网改写源地址，应辨认为？
答案 C。改的是离开本机时的源地址，链在 POSTROUTING。地址会变时手册要求用 MASQUERADE，固定地址才用 SNAT。DNAT 改的是目的地址。
Q7 · 公网访问防火墙外网口的 TCP 80，目的要改成 DMZ 的 192.168.10.8。应辨认为？
答案 A。进来就改目的地址，写 nat 的 PREROUTING 加 DNAT。SNAT / MASQUERADE 改的是源地址。改完地址后，转发仍要在 filter 的 FORWARD 放行，那是另一条规则。
Q8 · 本机只允许 SSH 与 HTTPS 的新连接。放行新连接应写成？
答案 A。本机服务用 INPUT；题干是 TCP 的 22 和 443；新连接状态写 NEW。FORWARD 是网关转发；80 不在本题放行名单里；DNAT 不能代替这条过滤规则。
