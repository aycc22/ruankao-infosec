开场：四本教材章都学完了，下午卷怎么写？

从 第 19 课 云计算 到 第 22 课 大数据，教程 第 23–26 章已全部覆盖。 本课不做新知识，而是把四块「安全工程」专题串成地图——下午卷最爱考「给场景 → 写风险 → 写措施」。 上午卷靠认概念；下午卷靠威胁对策成对写、每条一行、别空着。

结业测回顾：第 19–22 课平均约 7/7；历史易错点「等保测评 ≠ 风险评估」近几课已稳定答对。 本课重点：四场景秒判、下午卷答题模板、等保扩展怎么叠。

二、统一框架：安全工程五阶段

网站（L17）、云、工控、移动、大数据——教材里的「安全保护工程」都绕不开这五步：

阶段做什么下午卷怎么写
需求分析资产、威胁、合规、业务约束先列 3–5 条主要风险
安全设计架构、分区、控制措施选型写分区/隔离/访问控制方案
实施建设部署设备、加固、开发安全写具体措施（加密、WAF、VPN…）
测评验收等保测评、渗透、合规检查点等保 + 扩展；测评 ≠ 风险评估
运维保障监测、应急、补丁、审计写日志审计 + 应急预案
口诀（安全工程五阶段）：先分析后设计，实施测评再运维（字头：分设实测评运）。

三、下午卷万能答题模板

机考下午卷 4–5 道大题，写法比背更多细节更重要。记住这个骨架：

步骤写法示例句式
① 判场景一句话定性「本题属于工控 / 云多租户 / 移动 App / 大数据汇聚场景」
② 列风险每条「现象 → 后果」「公网暴露维护端口 → 远程入侵 PLC」
③ 写对策与风险一一对应「关闭公网端口；远程走 VPN + 审计」
④ 叠合规等保 + 扩展 / 法律「落实等保通用要求 + 工控扩展；关键数据出境须评估」
⑤ 收束监测 + 应急「部署日志审计与 SIEM；制定应急预案并演练」
口诀（下午卷案例答题模板）：先判场景列风险，对策成对写一行，合规扩展别漏项，监测应急来收束。
易错：只堆设备名词（「上防火墙、上 IDS」）不给针对本题风险的理由 → 扣分。每点写「因为…所以…」。

五、等保扩展怎么叠（下午卷常考一句）

保护对象写法额外关注点
云计算平台/租户系统通用要求 + 云计算安全扩展虚拟化隔离、镜像安全、租户数据残留
工业控制系统通用要求 + 工控扩展分区隔离、可用性、协议深度检测

七、混练测验（跨 19–22 课 · 点击选项立刻反馈）

Q1 · 某企业 IaaS 云主机 OS 补丁长期未打，Hypervisor 存在已知漏洞。最贴合的主要威胁是？
答案 B。IaaS 用户管 OS；Hypervisor 漏洞 → 逃逸/越权（L19 云特有威胁）。
Q2 · 水厂 PLC 对公网开放维护端口且使用默认口令。工控安全属性优先应强调？
答案 B。工控优先序：可用 > 完整 > 机密（L20）。
Q3 · 金融 App 将用户 Token 明文写入 SharedPreferences。最主要整改措施是？
答案 B。敏感令牌勿明文本地存储；配合 TLS 传输（L21 易错点）。
Q4 · 测试环境直接拷贝生产库明文手机号用于联调。应优先采用哪类技术？
答案 B。大数据隐私保护：测试/共享前脱敏；脱敏 ≠ 加密（L22）。
Q5 · 定级备案后委托有资质第三方按 GB/T 28448 做检查。这属于？
答案 B。等保测评 ≠ 风险评估（L11–12 / L18 易错点）。
Q6 · Which cloud deployment shares infrastructure among the public?（英文题）
答案 B。Public cloud = 对公众开放、多租户共享基础设施（L19）。
Q7 · 电力监控系统安全「十六字方针」核心强调？
答案 B。十六字：安全分区网络专，横向隔离纵向认（L20）。
附加题 A（下午卷 · 云计算）· 点击展开参考写法

某 SaaS 厂商多租户共享数据库，某租户通过 API 越权读取其他租户订单；释放云盘后旧数据可被恢复。请：（1）列主要风险；（2）写至少 6 条整改措施。

（1）主要风险
· 多租户越权 → 数据泄露、合规事故。
· 数据残留 → 释放资源后敏感信息可恢复。
· API 弱认证/过度授权 → 横向移动。

（2）整改措施
① 租户隔离：逻辑/物理隔离；行级租户 ID；禁止跨租户查询。
② 访问控制：API 最小权限 + OAuth/密钥轮换；管理面与业务面分离。
③ 加密：传输 TLS；存储加密；密钥托管（KMS）。
④ 防残留：释放存储前安全擦除/覆写；快照访问审计。
⑤ 监测审计：异常 API 调用告警；日志留存与 SIEM 关联。
⑥ 等保：通用 + 云计算扩展；定期测评整改。
模板：先写租户隔离与 API 权限 → 再写加密与防残留 → 监测 + 等保扩展。
附加题 B（下午卷 · 大数据 + 移动）· 点击展开参考写法

某公司 App 采集用户位置与通讯录上传至大数据平台；分析接口无审计；部分数据拟出境合作。请：（1）列风险；（2）写至少 6 条措施。

（1）主要风险
· App 过度采集 + 明文传输/存储 → 隐私泄露。
· 多源汇聚后边界模糊 → 责任不清、滥用难控。
· 分析接口无审计 → 越权与内部滥用。
· 跨境未评估 → 违反数据出境合规要求。

（2）整改措施
① 移动侧：最小必要采集；TLS 传输；本地敏感字段加密；应用加固防逆向。
② 分类分级：梳理数据资产；敏感字段标识与策略。
③ 隐私技术：汇聚前脱敏/匿名；必要时差分隐私。
④ 访问控制：分析接口 RBAC + 业务授权；最小权限。
⑤ 审计溯源：全链路操作日志；异常滥用监测。
⑥ 跨境合规：出境安全评估；重要数据境内存储要求。
⑦ 等保：通用 + 移动互联扩展 + 大数据扩展。
模板：移动采集最小化 → 大数据分级脱敏 → 审计 + 跨境评估。
